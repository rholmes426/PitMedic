Automobilista 2

Controller input or calibration is lost

AMS2 bindings may need to be rebuilt when controller configuration fails after a USB, driver, or device change.

Approval requiredActiveEvidence reviewed 2026-09-03Guide updated 2026-10-05

Checks and expected results

Before you repair it

  • A Reiza staff response on September 20, 2026 recommends disabling Steam Input for AMS2 when a wheel or paddles stop working. Record the prior per-game setting, close AMS2, test the AMS2-only override, then retest steering and paddles. Restore the prior setting if ineffective. Do not change the global Steam setting or apply this automatically to gamepads. The thread does not confirm success on the original poster's PC.
  • Check device visibility in Windows and record the wheel/pedal connections before blaming the saved configuration.
  • Close Automobilista 2 and preserve default.controllersettings.v1.03.sav before removing its active copy.
  • Note the settings you will need to re-enter and change only the identified file or files.

How to confirm the result

Relaunch Automobilista 2, review the rebuilt settings, and repeat the original action. Confirm that new bindings and calibration work for steering, pedals, and buttons in a test session. If it does not help, keep the new evidence and use the backup to restore the previous configuration with the simulator closed.

Repair limits and when to stop

You must remap and calibrate controls. A reset does not repair a missing device or guarantee stable USB enumeration.

How PitMedic recognizes it

AMS2 evidence identifies controller settings or default.controllersettings.v1.03.sav after an update, USB-port change, or driver change.

Signals PitMedic may recognize

  • default.controllersettings.v1.03.sav
  • controller config
  • calibration

Built-in response

Preserve and remove only default.controllersettings.v1.03.sav so wheel/controller bindings can be rebuilt without resetting unrelated game settings.

Repair safetySignificant / reversible / ask first
