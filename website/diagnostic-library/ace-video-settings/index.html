Assetto Corsa EVO

Broken video settings / graphics startup state

Startup fails during video initialization or a display change.

Automatic repair availableActiveEvidence reviewed 2026-09-01Guide updated 2026-09-29

Checks and expected results

Before you repair it

  • Confirm the current log names a video/graphics initialization failure; a normal settings-load line is not an error.
  • Close Assetto Corsa EVO and preserve Video.videosettings before removing its active copy.
  • Note the settings you will need to re-enter and change only the identified file or files.

How to confirm the result

Relaunch Assetto Corsa EVO, review the rebuilt settings, and repeat the original action. Confirm that the menu displays correctly and the same launch succeeds. If it does not help, keep the new evidence and use the backup to restore the previous configuration with the simulator closed.

Repair limits and when to stop

This touches video settings only. It does not reset controls or repair missing game content.

How PitMedic recognizes it

Assetto Corsa EVO exits during startup or logs point to video/graphics initialization. A Video.videosettings file exists in the ACE user-data folder.

Signals PitMedic may recognize

  • Video.videosettings
  • video settings
  • graphics startup

Built-in response

Back up and remove only Video.videosettings so the simulator can regenerate graphics settings without wiping controls and other user data.

Normal initialization text is not a fault

Verified automated regression test · 2026-09-28

Test setup

Synthetic lines included Loading Video.VideoSettings profile, ShaderCache initialized successfully, and BrowserData directory opened.

Observed result

Those normal lines produced no fault match. A separate HTTP 503 Service Unavailable line remained detectable for RaceRoom.

What this establishes

This verifies log matching only. Recognizing a 503 does not prove that clearing local browser data will fix a server-side failure.
