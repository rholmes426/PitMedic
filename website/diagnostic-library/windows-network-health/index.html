Diagnostic guidance

Windows

Local Windows connection drops or IP and DNS configuration problems

When a race or another app disconnects, local Windows network evidence can help narrow down the next check.

Guided diagnosisGuidanceEvidence reviewed 2026-11-27Guide updated 2026-11-27

Checks and expected results

PitMedic passively samples adapter state, usable addresses, configured gateways and DNS resolvers, and local packet counters. Recommendations are matched to the evidence.

Before you repair it

  • Review Home, under Windows & Network Health. There is no manual diagnostic button.
  • After the simulator closes, open its Last Session Network Report. Compare the first local sign and report counts with when the connection problem happened.

How to confirm the result

A link drop points toward checking Wi-Fi, Ethernet or VPN reconnects. Repeated address, gateway or DNS gaps point toward checking the corresponding configuration. Repeated local counter increases justify comparing cables, adapters or another device.

Repair limits and when to stop

Passive local samples can miss short drops, and intentional offline, LAN-only and VPN configurations may explain a finding. Interface counters are not a measurement of race-server latency or packet loss. PitMedic does not send probes, capture packets, change settings or reset adapters.

When to consider this guidance

Silently sample Windows adapter link state, address, gateway, DNS configuration and local packet counters. Distinguish repeated configuration gaps from isolated readings, and save aggregate evidence with the last simulator session.

Suggested manual checks

Review the evidence in Home or Last Session. Verify the intended adapter, router or DHCP, and DNS or VPN configuration according to the specific finding. No automatic reset or active probe.
